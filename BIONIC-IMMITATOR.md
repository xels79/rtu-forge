# Bionic Immitator

`bionic-immitator` — русскоязычный цифровой имитатор физической установки
Bionic Mini. Контроллером остаётся настоящая плата Bionic Mini: программа
исполняет полученные команды и рассчитывает воду, давление, датчики и аварии,
но никогда не формирует собственный `STOP`.

## Запуск

```powershell
uv run bionic-immitator --home .\bionic-data
uv run bionic-immitator --home .\bionic-data --no-controller
uv run bionic-immitator --home .\bionic-data status
uv run bionic-immitator --home .\bionic-data help
```

Интерактивный запуск открывает полноэкранный интерфейс с отдельными страницами
`status`, `devices`, `ports`, `settings`, `help`, `log`, `rs485`, `tanks`,
`pumps`, `pressure`, `irrigation`, `light`, `sensors`, `water`, `ponics`,
`ponics settings`, `ponics registers`, `drives`, `drive hp1` и `drive hp2`.
Страница `status`
содержит только состояние установки и три последних события; вывод команд не
накапливается в центральной области. Командная строка всегда остаётся внизу,
перерисовка не выполняет физический расчёт и не стирает набираемую команду.

`F1`–`F6` открывают соответственно справку, настройки, статус, устройства,
порты и журнал; на странице настроек `F5` применяет черновик. `Esc` возвращает
предыдущую страницу. `PgUp`/`PgDn` и колесо
мыши прокручивают текущую страницу. В настройках строку можно выбрать кликом
или `Alt+J`/`Alt+K`, а `Enter` на пустой командной строке начинает её
редактирование. `Alt+A` применяет черновик, `Ctrl+S` сохраняет его. Стрелки
`↑`/`↓` используют сохраняемую между запусками историю из 500 команд. `Tab`
дополняет команды, подкоманды и физические имена объектов.

В верхней строке каждого экрана постоянно видны состояние и масштаб времени:
`СИМУЛЯЦИЯ: РАБОТАЕТ` либо `СИМУЛЯЦИЯ: ПАУЗА`, а также
`СКОРОСТЬ: ×1.0`. В `view help` команды собраны в отдельном разделе
`УПРАВЛЕНИЕ СИМУЛЯЦИЕЙ`:

```text
sim start            Запустить расчёт физики
sim pause            Приостановить расчёт физики
sim resume           Продолжить расчёт
sim speed 1          Нормальная скорость
sim speed 5          Пятикратная скорость
sim reset --confirm  Сбросить виртуальное состояние
sim state save <имя>
sim state load <имя> --confirm
sim state list
```

`sim pause` замораживает только расчёт физики: RS485 остаётся открытым, а
команда остановки плате не отправляется.

`--no-controller` полезен для разработки без USB №1. Справка, статус, список
устройств и изменение offline-настроек никогда не открывают последовательный
порт. Ручная запись виртуального исполнительного выхода доступна только после
явного запуска с `--test-mode` и журналируется как тестовое вмешательство.

## Два USB

- USB №1 — Modbus RTU slave. Программа владеет портом единолично, принимает
  команды платы и отвечает от имени виртуальных устройств.
- USB №2 — Modbus RTU master для физического Waveshare Relay 8/16CH. По
  умолчанию `hardware_mode=false`: порт не открывается и физические реле не
  активируются. После явного включения сохраняются раздельные `desired` и
  подтверждённые FC01 `confirmed` состояния; успешный FC0F сам по себе не
  считается подтверждением положения.

## Дискретные датчики уровня

Восемь виртуальных датчиков уровня управляют сухими контактами физического
Waveshare Relay на USB №2. Они не эмулируются как дополнительные Modbus-
устройства на USB №1. Начальная карта каналов:

| Канал | Датчик | Назначение |
|---:|---|---|
| CH1 | `bo-min` | Осмос: минимальный уровень |
| CH2 | `bo-max` | Осмос: максимальный уровень |
| CH3 | `bp-min` | Бульон: минимальный уровень |
| CH4 | `bp-max` | Бульон: максимальный уровень |
| CH5 | `bso1-min` | Дренаж 1: минимальный уровень |
| CH6 | `bso1-max` | Дренаж 1: максимальный уровень |
| CH7 | `bso2-min` | Дренаж 2: минимальный уровень |
| CH8 | `bso2-max` | Дренаж 2: максимальный уровень |

По умолчанию `sensor_hysteresis_l=0` и `sensor_delay_s=0`: расчётный сигнал
меняется на пороге без искусственной задержки. Оба механизма можно включить в
настройках. Мост отправляет FC0F только при смене требуемого образа, а затем
отдельно проверяет его через FC01. При потере связи подтверждённое состояние
становится неизвестным и экран показывает `НЕТ СВЯЗИ`, а не последнее значение.

Каждый из восьми датчиков имеет отдельный абсолютный порог в литрах. Для бака
проверяется `0 ≤ MIN < MAX ≤ физическая ёмкость`. Порог MAX обозначает только
высоту установки датчика: его срабатывание не делает бак полным и не закрывает
клапан. Перелив начинается лишь после исчерпания физической ёмкости. Изменение
ёмкости не перемещает датчики и не пересчитывает их пороги. `view sensors` и
`view settings` показывают порог одновременно в литрах и процентах текущей
ёмкости. Изменение выполняется командой `sensor <id> threshold <л>`, после чего
`settings save` явно сохраняет черновик для следующего запуска.

`sensor_relay_contact=NO|NC` документирует, какие контакты использованы при
монтаже. `CH1` означает управляемый канал, а не конкретный винтовой зажим.
Электрическое замыкание входа зависит одновременно от NO/NC и
`sensor_relay_active_low`; поэтому логическое `ВКЛ` само по себе не является
утверждением о замкнутом контакте. `view sensors` показывает расчётный сигнал,
требуемое и подтверждённое состояния, FORCE/AUTO и доступность USB №2.

USB №1 и USB №2 не могут использовать один COM-порт. Изменение портов,
параметров линии или адресов в черновике применяется через `settings apply` с
остановкой прежних соединений и безопасным переподключением. `settings save`
записывает черновик, но не применяет его к работающему процессу.

## Освещение

`view light` показывает все шесть ярусов, включая выключенные и не имеющие
светильника. Для каждого видны русское название, стеллаж/ярус, тип
`NONE`/`SINGLE`/`SPECTRAL_4`, реле DO, состояние питания, физический Modbus ID
и AO, записанное платой напряжение и расчётная яркость. Для стандартного
диапазона 0–10 В используется формула `напряжение / 10 × 100`. Это задание
управляющего сигнала, а не измерение световой мощности.

AO-регистры не обнуляются при отключении реле питания. Поэтому при сохранённых
7 В и выключенном DO экран показывает задание 7 В / 70%, но фактический свет
`ВЫКЛ`. Для `SPECTRAL_4` красный, дальний красный, синий и белый каналы
показываются отдельно. На главном экране перечислены только ярусы с включённым
питанием света.

`view light settings` содержит отдельную строку каждого яруса и различает
заводской, применённый, сохранённый и черновой профили. Доступны команды:

```text
light set zone-1 type NONE|SINGLE|SPECTRAL_4
light set zone-1 rack 1
light set zone-1 tier 1
light set zone-1 relay 3
light set zone-1 enabled on|off
light set zone-1 name "Стеллаж 1, ярус 1"
light set zone-1 channel brightness 2 1
light set zone-2 channel red 2 2
light set zone-1 voltage 0 10
light set zone-1 brightness 0 100
light apply
light save
light restore-defaults
```

При смене типа создаётся требуемый набор полей, но физические AO не подбираются
автоматически: оператор назначает их сам. Неполный профиль и конфликты DO/AO
видны на странице и не могут быть применены или сохранены. `F5` применяет
только свет, `Ctrl+S` сохраняет только свет, `Esc` возвращается без применения.
Восстановление профиля Bionic Mini меняет только черновик освещения и не
затрагивает баки, насосы, датчики, Modbus-регистры или физические выходы.

## Проверенный профиль Stage 7

| Адрес | Виртуальное устройство | Реализованные функции/регистры |
|---:|---|---|
| 1 | Waveshare Relay 32CH | FC01/02, FC05, FC0F; coils 0..31 |
| 2, 3, 4 | Waveshare AO 8CH(B) | FC03/06/10; holding 0..7, 0..10000 mV |
| 5 | PonicPilot 32 | FC03/06/10; holding PDU 0..41 |
| 6 | Waveshare AI | FC04; input 0..7; AI1 LOW, AI2 HIGH в µA |
| 7 | Innovert IDD222M21E HP1 | FC03/06 |
| 8 | Innovert IDD222M21E HP2 | FC03/06 |

IDD использует команды `0x2000` (`1=STOP`, `2=RUN`, `0x10=RESET`) и
`0x2001` (0,1 Гц). Телеметрия PA.01/PA.02/PA.03/PA.04/PA.27/PA.28 доступна
только для чтения в RAW-регистрах `1, 2, 3, 4, 27, 28`. PA.03 содержит
расчётный выходной ток с дискретой 0,1 А, PA.27 — только штатный код ошибки
IDD, PA.28 — подтверждённое состояние выхода ПЧ.

Подтверждённые RW-параметры: PB.00/PB.01/PB.02/PB.05/PB.06/PB.07/PB.08
(`100, 101, 102, 105, 106, 107, 108`), PC.10/PC.12/PC.15
(`210, 212, 215`),
PH.00/PH.01/PH.02 (`700, 701, 702`) и Pi.16 (`816`). Частота, времена и
номинальный ток имеют дискрету 0,1. Изменение PH.02
подтверждается по старому адресу, после ответа виртуальный прибор переходит на
новый свободный ID; сохранение в профиль остаётся отдельной командой
`settings save`. Изменение скорости или формата связи применяется после
ответа и делает прибор недоступным на несовпадающей линии, как физический ПЧ.

PB.02 строго выбирает источник RUN: `1` — физическая клемма, `2` — Modbus.
Сигналы не объединяются через OR. В обоих случаях требуется отдельный сигнал
выбора HP. Запись задания частоты не подделывает подтверждение RUN.

## Отказы насосов и штатная защита IDD

Для трёх насосов перекачки и HP1/HP2 автоматически моделируется цепочка
`HEALTHY → DRY_RUNNING → OVERHEATED → DEGRADED → FAILED`. Сухой ход начинается,
если команда платы активна, но насос не может получить воду. Возвращение воды
или снятие команды прекращает сухой ход и охлаждает оборудование, однако
накопленный износ и физический отказ не исчезают. Снижение производительности
влияет на реальный расход, а для HP — также на напор и весь контур полива.

Для HP1 и HP2 раздельно моделируются заклинивание, повреждение рабочего
колеса, отказ двигателя и потеря заливки. Они меняют расчётные ток, нагрузку,
напор и расход, но не изменяют RUN/selector платы.
Заклинивание может вызвать штатную защёлкнутую ошибку перегрузки IDD в PA.27;
для `oL2` руководство mini PLUS задаёт десятичный код `10`. Демонстрационная
защита по умолчанию использует порог `1,5 × Iном` и выдержку 60 с; эти
параметры модели не выдаются за дополнительные Modbus-регистры. При
отключённой защите имитатор не выполняет безопасный STOP. RESET очищает
ошибку ПЧ, но не ремонтирует механику. `alarm reset all` также не ремонтирует
оборудование.

`view equipment` показывает команду платы, фактическую работу, доступность
воды, расход/давление, текущую стадию, время сухого хода, нагрев, износ, причину
отказа и необходимость ремонта. Явные операции обслуживания:

```text
equipment list
equipment status <id>
equipment repair <id> --confirm
equipment replace <id> --confirm
equipment sync-wear <id>
```

Ремонт и замена не изменяют DO, RUN-регистр или selector, не сбрасывают чужие
повреждения и не выполняют RESET частотника. Если команда платы остаётся
активной, интерфейс предупреждает о возможном немедленном запуске.

Отдельный `equipment_profile` хранит для каждого из пяти насосов собственные
пороги предупреждения, перегрева, деградации и отказа, скорости нагрева,
охлаждения и износа, снижение производительности, начальное состояние и тип
критического отказа. Поля редактируются через
`equipment set <id> <поле> <значение> [--sync-wear]` и применяются/сохраняются обычными
`settings apply` / `settings save`. Начальное состояние используется при
следующем `sim reset --confirm` или запуске.

`failure_s` и `wear_rate_per_s` являются независимыми механизмами отказа.
Интерфейс показывает, какой сработает раньше. Ключ `--sync-wear` либо команда
`equipment sync-wear <id>` пересчитывают скорость износа под заданный порог,
не сбрасывая уже накопленное повреждение.

На странице `view settings` все поля профиля каждого насоса вынесены в
отдельные редактируемые строки. Начальные времена: 120 с для
БО → БП, БСО1 → БП и БСО2 → БП; 180 с для HP1 и HP2. Строки помечены как
`расчётное`: эти времена не измерены на конкретных насосах. Остальные настройки
разделены по русским названиям подсистем, а внутри каждой группы отсортированы
по русской подписи параметра.

Именованные контрольные точки `sim state ...` хранят физическое состояние
отдельно от INI. Они включают воду, состав, повреждения, аварии, потери и
разрыв трубы, но намеренно не восстанавливают DO, AO и RUN-команды платы.

Тип поломки, накопленное повреждение и причинно-следственная диагностика
остаются внутренними данными имитатора. Новых дискретных входов и Modbus-
регистров для них нет. Плата видит только штатные PA-регистры IDD, аналоговое
давление и существующие физические датчики.

## PonicPilot 32 и состав раствора

PonicPilot жёстко обслуживает только общий бак `bp`: выбора бака в настройках
нет. pH, EC и температура берутся из состава БП, а дозы A/B/C, pH+ и pH−
изменяют только его. БО и оба БСО имеют собственный состав, который меняется
при заполнении, поливе, возврате и перекачке. Отдельных химических регуляторов
для этих баков нет. Заголовок каждой страницы PonicPilot постоянно содержит
`Бак: БП (Бульон)` и `ДЕМО: показания рассчитаны имитатором`.

Карта подтверждена руководством Ponics Pilot 32: ручные адреса 1..42
соответствуют PDU 0..41. Firmware Bionic читает именно PDU 0..41 блоками и
разрешает своей сервисной записи FC06 только PDU 8, 9, 23, 24, 26..39.

Карта реле профиля хранится в модели как профиль, а не в расчётных формулах:

| Функция | Выход |
|---|---:|
| Подпор | do-1 |
| Осмос → бульон | do-2 |
| Ярусы 1..6 | do-9..do-14 |
| Дренаж 1 → бульон | do-17 |
| Дренаж 2 → бульон | do-18 |

| RUN HP2 / HP1 | do-31 / do-32 |

Освещение использует отдельные do-3..do-8 и фактические AO bindings Stage 7;
они не пересекаются с do-9..do-14 полива. Поддержаны одно- и
четырёхканальные ярусы.

## Физическая модель

Баки `bo`, `bp`, `bso1`, `bso2` независимы. Объём ограничен нулём и ёмкостью,
а избыток накапливается как перелив. Маршруты `bso1 → bp` и `bso2 → bp`
работают только при включённых do-17 и do-18 соответственно; самопроизвольного
возврата дренажа нет.

У каждого бака отдельно хранятся условная масса солей, буфер кислотности и
теплосодержание. Поэтому перекачка переносит состав вместе с объёмом, EC
вычисляется из массы и объёма, а pH смешивается через буфер, не как обычное
арифметическое среднее. Полив отдельно учитывает потерю воды, поглощение
питательных веществ и осаждение. Это демонстрационная модель, не пригодная для
управления реальным химическим дозированием.

Давление калибровано по двум предоставленным точкам: 29 Гц/3 яруса ≈ 30 бар и
42 Гц/3 яруса ≈ 57 бар. Остальные значения являются приближённой моделью.
Учитываются число и фактические положения клапанов ярусов, частота HP, клапаны
источника, насос подпора и наличие воды. Закрытие ярусов уменьшает расход и
быстро приближает давление к напору закрытой задвижки; открытие увеличивает
расход и быстро снижает давление. Разгон HP отдельно использует более плавный
`pressure_rise_s`.

Засор расположен после точки измерения HIGH. Он рассчитывается как увеличение
гидравлического сопротивления: с ростом `blockage_severity` расход через
открытые ярусы уменьшается, а давление перед препятствием растёт. При
остановленном HP засор давления не создаёт. `fault blockage off` устраняет
препятствие, но не ремонтирует уже разрушенную трассу.

Переключение клапанов использует отдельные времена открытия и закрытия в
миллисекундах. Необязательный переходный скачок участвует в проверке порога
разрушения; по умолчанию его коэффициент равен нулю, поскольку это параметр
демонстрационной модели, а не измеренная характеристика гидроудара. При пороге
75 бар труба остаётся `RUPTURED`, HIGH быстро падает до 0–3 бар и вода
продолжает теряться до `pipe repair`; выходы платы и команда RUN не меняются.
Страница `view pressure` показывает частоту и RUN/STOP, все клапаны, источник,
расход, текущее и целевое давление, последний скачок, максимум и состояние
трассы.

Перелив, разрыв и недостаток воды разделяют текущее состояние и фиксацию.
`alarm reset all` не ремонтирует трубу, не возвращает воду и не меняет команды.
`fault clear all` отключает протечку/засор, но для трубы всё равно требуется
`pipe repair`.

При `sim pause` физические параметры заморожены, а Modbus продолжает отвечать
текущими неизменёнными значениями. `sim speed` масштабирует только физический
шаг и не меняет UART/Modbus тайминги.

## Настройки

По умолчанию используется `<home>/bionic-immitator.ini`. Файл не создаётся и
не перезаписывается без `settings save`. Доступные mutable options перечислены
в `bionic_config.OPTION_SPECS`:

| Категория | Параметры |
|---|---|
| serial | `controller_port`, `controller_baudrate`, `controller_parity`, `controller_stopbits`, соответствующие `sensor_relay_*` параметры линии |
| devices | `relay_address`, `ao1_address`, `ao2_address`, `ao3_address`, `ai_address`, `hp1_address`, `hp2_address`, `sensor_relay_id`, `sensor_relay_channels`, `sensor_relay_active_low`, `sensor_relay_contact`, `sensor_relay_map`, `sensor_relay_loss_behavior` |
| simulation | `hardware_mode`, `model_interval_ms`, `ui_interval_ms`, `retention_days` |
| tanks | ёмкости/начальные объёмы четырёх баков, `fill_flow_lpm`, расходы трёх насосов |
| irrigation | расход ярусов каждого стеллажа, доля и задержка возврата |
| sensors | восемь независимых абсолютных порогов MIN/MAX, общий гистерезис и задержка |
| equipment | отдельные профили развития повреждений трёх насосов перекачки и HP1/HP2 |
| pressure | подпор, времена набора/спада HP, времена реакции на открытие/закрытие клапанов, коэффициент/длительность переходного скачка, напор закрытой задвижки, порог/остаток разрыва и максимум модели |
| faults | параметры протечки и степень засора |
| lighting | независимый профиль шести ярусов: тип, DO, AO-привязки, диапазоны и включение |
| ponics | фиксированный `ponics_address=5`, режим, подтверждённые WEB-параметры pH/EC/полива/термостата |
| ponics_chemistry | профили воды, начальный состав БП/дренажей, буфер, поглощение, осаждение и коэффициенты реагентов |
| drive_hp1 / drive_hp2 | PB.00/PB.01/PB.02/PB.05/PB.06, PC.10/PC.12/PC.15, PH.00/PH.01, Pi.16, разгон/торможение, нагрузка и механический отказ |

Адреса USB №1 обязаны быть уникальны и лежать в 1..247. Карта второго реле
задаётся строкой `датчик:канал` и обязана назначить все восемь MIN/MAX датчиков
уникальным каналам.

## Журнал

`bionic-events.jsonl` хранит события последних семи суток между перезапусками,
с ограничением памяти. Повторяющееся физическое событие не записывается на
каждом шаге: фиксируются начало и завершение. Экспорт выполняется в UTF-8 CSV:

```text
view log
log last 100
log filter alarms
log export events.csv
```

## Непроверенные аппаратные допущения

- Реальная гидравлическая привязка «стеллаж 1 → дренаж 1, стеллаж 2 → дренаж
  2» должна быть подтверждена на стенде.
- Давления вне двух калибровочных точек расчётные, а не измеренные.
- Полярность и каналы физического реле датчиков должны быть проверены до
  `hardware_mode=true`.
- DO19/DO20 используются как физические selector-сигналы HP1/HP2 согласно
  профилю Bionic Mini. Исходники firmware и стенд в этой сессии недоступны,
  поэтому электрическая трассировка этих двух линий аппаратно не подтверждалась.
- Аппаратная проверка двух USB, реального Waveshare и IDD в этой реализации не
  заявляется; автоматические тесты используют только fake serial.
- Адресная база PonicPilot и канал дозатора B подтверждены локальной записью
  испытаний реального прибора; остальные строки карты взяты из руководства и не
  выдаются за повторно проверенные на этом стенде. Исходники драйвера Bionic Mini
  в доступной рабочей области отсутствовали, поэтому сверка с firmware не
  заявляется.
- Карта IDD проверена по официальным руководствам INNOVERT IDD mini PLUS и
  Modbus RTU. Физический IDD222M21E и переход параметров связи на реальном
  RS-485 в этой ревизии не испытывались.
