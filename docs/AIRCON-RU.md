# RTU Forge Aircon: Hisense AUC-18HR4SAA1 и ONOKOM HS-6-MB-B

## Установка в Windows

Откройте PowerShell в каталоге репозитория и выполните:

```powershell
.\setup.ps1
```

Установщик обновляет существующий `rtuforge.exe` и не перезаписывает
пользовательские `config.ini`, `scripts.ini` и историю. После установки откройте
новое окно CMD и проверьте демо-режим без оборудования:

```cmd
rtuforge.exe aircon --demo
```

В демо-режиме работают экран, команды и подтверждающее чтение, но COM-порт не
открывается. Для одного неинтерактивного снимка экрана можно выполнить
`rtuforge.exe aircon --demo --snapshot`.

## Подключение

1. При снятом питании подключите адаптер HS-A6 к разъёму кондиционера
   `CN18 WIRED CON` согласно паспорту ONOKOM и Hisense.
2. Соедините HS-A6 со шлюзом HS-6-MB-B штатным кабелем.
3. Подключите линии A/B и общий провод RS485 к преобразователю, соблюдая
   полярность и требования производителя к питанию и оконечному сопротивлению.
4. Не запускайте на одной линии два Modbus-master одновременно.
5. Заводские параметры шлюза: `9600`, `8N2`, Modbus ID `1`.

Основной запуск из CMD:

```cmd
rtuforge.exe --port COM7 --baudrate 9600 --bytesize 8 --parity N --stopbits 2 aircon
```

`COM7` — пример. Выберите фактический порт командой `ports` или клавишей F3.
Параметры командной строки действуют только в текущем процессе, имеют приоритет
над `aircon.ini` и не изменяют общий `config.ini`.

## Первый безопасный сеанс

Приложение не включает кондиционер при запуске. Если автоматическое подключение
выключено, введите:

```text
connect
status
```

Сначала проверяется ответ шлюза по Coil 20. Поэтому экран различает два случая:

- «Шлюз: НЕТ СВЯЗИ» — корректного ответа Modbus нет;
- «Шлюз: НА СВЯЗИ, Кондиционер: НЕТ СВЯЗИ» — шлюз отвечает, но связь с
  кондиционером через HS-A6 не подтверждена.

Старые значения после потери связи не показываются как свежие. Фоновый опрос
по умолчанию выполняется раз в 2 секунды и использует только чтение.

## Команды и клавиши

```text
on                         включить кондиционер
off                        выключить кондиционер
status                     немедленно обновить состояние
temp 23                    задать 23 °C (целое значение 16..30)
mode heat|cool|auto|dry|fan
fan auto|1|2|3
ports                      показать последовательные порты
connect / disconnect
settings                   открыть экран настроек
set <имя> <значение>       сохранить параметр в aircon.ini
help                       открыть русскую справку
exit                       выйти
```

Клавиши: F1 — справка, F2 — статус, F3 — порты, F4 — настройки, Esc — назад.
Tab включает автодополнение, Up/Down используют постоянную историю команд.
Последние две строки TUI всегда отведены под результат операции и ввод команды.

Безопасная диагностика из CMD выполняет только документированные чтения:

```cmd
rtuforge.exe --port COM4 --baudrate 9600 --bytesize 8 --parity N --stopbits 2 aircon diag
```

Команда читает Coil 20, Coil 100, Coil 1, Holding 1..3, 5..7, 21, 23, 32,
аппаратную версию, версию прошивки и сигнатуру даже тогда, когда Coil 20 равен
нулю. Она показывает полный TX/RX, CRC, время, raw HEX, знаковую расшифровку и
оценку доступности температур и не отправляет FC05/FC06.

Каждая управляющая команда сначала проверяет аргументы, выполняет ровно одну
документированную запись, проверяет Modbus-ответ и повторно читает состояние.
Успешная запись не выдаётся за подтверждение работы компрессора: фактическое
состояние термостата читается отдельно.

## Настройки

Файл `%APPDATA%\RTUForge\aircon.ini` создаётся только после явной команды `set`.
Доступные имена:

- `port`, `baudrate`, `bytesize`, `parity`, `stopbits`, `timeout_ms`;
- `slave_id`, `poll_interval_ms`, `auto_connect`;
- `humidity_enabled`, `humidity_slave_id`, `humidity_register_type`;
- `humidity_address`, `humidity_scale`, `humidity_stale_ms`;
- `diagnostic_log`.

Примеры:

```text
set port COM7
set slave_id 1
set poll_interval_ms 2000
set auto_connect true
```

Изменение параметра соединения отключает открытый порт до следующей команды
`connect`. Сервисные регистры скорости, чётности, стоповых битов и Modbus-адреса
самого шлюза приложение не записывает.

## Реализованная карта ONOKOM

Адреса ниже передаются в PDU напрямую, без вычитания единицы. Это соответствует
официальным шаблонам ONOKOM для Wiren Board и SprutHub.

| Адрес | Функция | Использование |
|---|---|---|
| Coil 1 | FC01 / FC05 | питание, чтение и явная команда on/off |
| Coil 20 | FC01 | связь шлюза с кондиционером |
| Holding 1 | FC03 / FC06 | режим 1..5 |
| Holding 2 | FC03 | активное состояние и режим 0..5 |
| Holding 3 | FC03 | температура помещения, signed × 0,01 °C |
| Holding 5 | FC03 / FC06 | уставка 1600..3000, шаг 100 |
| Holding 6 | FC03 | состояние термостата 0..2 |
| Holding 7 | FC03 / FC06 | вентилятор 0..3 |
| Holding 21 | FC03 | текущая мощность компрессора 0..100 % |
| Holding 23 | FC03 | температура теплообменника, signed × 0,01 °C |
| Holding 32 | FC03 | фактическая скорость вентилятора 1..3 |

Holding 3 никогда не записывается приложением. Управляющие команды используют
отдельные разрешённые Holding 1 и Coil 1; активный режим подтверждается чтением
Holding 2. Недокументированный Holding 4 не читается.

В протоколе нет отдельного признака достоверности температур. Для проверенной
связки AUC-18HR4SAA1 + HS-A6 C устойчиво повторяющаяся одновременно пара
Holding 3 = `0x0000` и Holding 23 = `0xF830` подтверждена как отсутствие
телеметрии: после трёх последовательных циклов экран показывает «НЕТ ДАННЫХ».
Отдельные значения 0,00 °C или −20,00 °C остаются допустимыми и не скрываются.
Holding 6 = 0 означает «ПРОСТАИВАЕТ», а не ошибку; Holding 7 задаёт выбранную
скорость, тогда как Holding 32 сообщает фактическую скорость вентилятора.

## Влажность и ограничения

У HS-6-MB-B нет документированного регистра относительной влажности. Поэтому по
умолчанию показывается «НЕТ ДАТЧИКА». Можно настроить отдельный Modbus-датчик на
той же линии: его ID, FC03/FC04, адрес и коэффициент задаются параметрами
`humidity_*`. Если последнее успешное значение старше `humidity_stale_ms`, экран
показывает «НЕТ СВЕЖИХ ДАННЫХ».

`mode dry` лишь включает штатный режим осушения кондиционера. Программа не
поддерживает автоматическую уставку RH и не выдаёт этот режим за полноценное
регулирование влажности.

## Диагностика

На экране отдельно считаются тайм-ауты, ошибки CRC и прочие ошибки обмена.
Опрос и ручные команды проходят через один lock, поэтому две транзакции не могут
одновременно использовать COM-порт. После разрыва связи программа не повторяет
записи `on`, `mode`, `temp` или `fan`; решение о повторе всегда принимает оператор.

Перед работой с физическим кондиционером получите разрешение оператора. В
автоматических тестах используется эмулятор; реальную разводку, помехоустойчивость
RS485 и поведение конкретной прошивки необходимо проверять отдельно на стенде.
