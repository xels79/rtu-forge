# Waveshare AO: четырёхканальная система света в RTU Forge

Свет управляется **внутри `rtuforge`**, в обычной консоли и через one-shot команду. Отдельной программы и нового COM-подключения не требуется.

## Поддерживаемый протокол

Режим для Waveshare AO с выходами **0–10 В**, управляющими holding-регистрами 0..3, значение в мВ (0..10000). Перед использованием проверьте, что ваша модификация модуля применяет эту карту, а не режим 4–20 мА или иной протокол. Состояние определяется по FC03, запись выполняется FC06 и проверяется повторным чтением. Все запросы включают Modbus CRC16 и проверку slave ID, функции, длины, CRC, исключений и эха записи.

Напряжение в статусе **рассчитывается по прочитанному значению регистра**, а не измеряется мультиметром. 0% = 0.000 В, 50% = 5.000 В, 100% = 10.000 В. При ошибке любого канала статус выдаёт ошибку, не скрывая её. `light all` пишет каналы последовательно; при сбое предыдущие успешные записи не откатываются.

## Установка

Получите актуальную `main`, затем обновите установленную команду:

Windows:
```powershell
git switch main
git pull --ff-only origin main
.\setup.ps1
```

Linux:
```bash
git switch main
git pull --ff-only origin main
./setup.sh
```

Для разработки можно использовать `uv run rtuforge` без установки. Полные инструкции по Python и uv: [README](../README.md) и [HELP-ENVIRONMENT](HELP-ENVIRONMENT.md).

## Запуск и подключение

Windows, пример COM7:
```powershell
rtuforge --port COM7 --baudrate 9600 --parity N
```

Linux:
```bash
rtuforge --port /dev/ttyUSB0 --baudrate 9600 --parity N
```

При постоянной настройке запустите `rtuforge` и внутри консоли:
```text
set options port COM7
set options baudrate 9600
set options parity N
light set address 1
light config
```

Настройте также `bytesize` и `stopbits` по паспорту платы; настройки другого оборудования могут отличаться. `--port` и прочие глобальные аргументы действуют только для текущего запуска и имеют приоритет над сохранёнными.

## Команды

```text
help light
light help
light config
light status
light 1 100
light channel 2 50
light 3 25.5
light all 0
light set address 1
light set channel 1 1
```

- `light status`: читает каждый AO1..AO4 и показывает яркость (%) и вычисленное напряжение в вольтах.
- `light 1 100`: записывает 100% на первый **логический** канал, подтверждает FC06 и перечитывает FC03.
- `light channel 2 50`: второй логический канал 50%, 5 В.
- `light all 0`: поочерёдно выключает четыре выхода, каждый с подтверждением. Не является аппаратным аварийным выключением.
- `light config`: без подключения показывает адрес, порт и сопоставление каналов.
- `light set address 1`: сохраняет Modbus slave ID 1..247 в `config.ini`.
- `light set channel 1 3`: назначает логическому каналу 1 физический AO3, **меняет местами** назначения, если AO3 уже занят. Так каждый физический выход используется ровно один раз.

Изменение соответствия каналов не меняет физические выходы и не отправляет команду на светильники. Значения выходов **не сохраняются и не выставляются автоматически при запуске**. Сохраняются только адрес и сопоставление каналов.

## Настройки config.ini

```ini
[light]
light_address = 1
light_channel_1 = 1
light_channel_2 = 2
light_channel_3 = 3
light_channel_4 = 4
```

При существующем старом `config.ini` раздел `[light]` подставляется по умолчанию в памяти, а записывается при выполнении `light set ...`; остальная конфигурация сохраняется. Порт и параметры интерфейса остаются в общем `[connection]` и управляются стандартной командой `set options`.

## Примеры one-shot

```powershell
rtuforge --port COM7 --baudrate 9600 --parity N light status
rtuforge --port COM7 --baudrate 9600 --parity N light 1 100
rtuforge --port COM7 --baudrate 9600 --parity N light all 0
```

## Если не работает

- Нет ответа: проверьте порт, ID, скорость, чётность, общую землю, линии A/B и питание платы.
- Ошибка CRC, slave ID или Modbus exception: проверьте карту регистров и протокол конкретного модуля.
- Включён второй master: отключите его, одной шиной RS-485 должен управлять один мастер.
- Проценты в статусе отличаются от записанных: система сообщает об ошибке подтверждения; проверьте модуль.
- Нельзя считать программное `light all 0` независимым аппаратным аварийным отключением питания.
